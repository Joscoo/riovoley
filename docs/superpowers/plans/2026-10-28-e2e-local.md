# Plan: Supabase local y E2E autenticados

Spec: ../specs/2026-10-28-e2e-local-design.md

## Restricciones globales

Solo escrituras locales con datos ficticios, sin cambios de producción ni de secretos existentes. Preservar auditoría anterior y cambios sin versionar. Implementación directa en esta sesión, sin commits/push ni nueva arquitectura de producto. El aislamiento se implementa en Docker/runtime, manteniendo disponibles node_modules y pruebas de la copia actual.

## Review Focus

- URL remota, puerto inesperado o credenciales incompletas deben bloquear el lanzamiento antes de una escritura.
- Un servidor CRA previo podría conservar configuración de producción: proceso/build propio y variables explícitas.
- Dumps y migraciones parciales no acreditan paridad: revisar inventarios y registrar divergencias.
- Idempotencia del seed: no duplicar cuentas/datos ficticios en cada ejecución.
- Peticiones externas de funciones/correo y tokens en trazas: aislar servicios y revisar privacidad.

## Tareas

1. Comprobar Docker/WSL, iniciar motor y preparar CLI fijada en runtime ignorado. Guardar diagnósticos con exit code. No modificar el entorno nativo Android.
2. Escribir pruebas node:test para guardias de destino local, configuración de navegador y redacción. Observar el fallo antes de implementar helpers en scripts/e2e/local/.
3. Preparar config Supabase local y bootstrap SQL revisado desde estructura de aplicación; aplicar solo al PostgreSQL Docker identificado por id local. Verificar tablas, vistas, RLS y funciones requeridas.
4. Crear seed de tres roles y fixtures de módulos. Verificar Auth local y consultas por rol; probar repetición sin duplicados.
5. Preparar lanzador CRA/Playwright que hereda únicamente variables autorizadas para el entorno y rechaza cualquier backend no local. Ejecutar smoke escritorio y depurar infraestructura sin cambiar producto.
6. Ejecutar suites pendientes en siete perfiles, conservar JSON/HTML/capturas/códigos y resultados de mutaciones locales. Cambios de tests solo con justificación documentada de selectores o contratos vigentes.
7. Documentar operación y resultados, controles de privacidad e inventario. Revisión final independiente del arnés de aislamiento y verificación de cambios.
