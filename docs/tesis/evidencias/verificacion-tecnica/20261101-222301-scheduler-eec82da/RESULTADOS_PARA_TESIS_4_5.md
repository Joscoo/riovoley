# Propuesta para revisión académica del apartado 4.5

Como verificación complementaria del 1 de noviembre de 2026, se ejecutaron 12 pruebas Node de las guardas para configurar el secreto del scheduler y diez pruebas de regresión del módulo de respaldo, todas aprobadas. El grupo de 26 casos de configuración incorporó los mismos 12 casos del scheduler, diez del parser Auth y cuatro del parser de actividad Android, por lo que no se suman sus repeticiones como pruebas únicas. Estos contratos utilizaron dependencias sintéticas y se distinguen del ensayo con la CLI real, que transmitió exactamente una entrada mediante una tubería Windows a una API simulada exclusivamente en HTTP local. El flujo de protección comprobó DPAPI y GPG reales con una fixture, sin acceso institucional ([guardas](unitarias/scheduler-cli-esquema-verde.stdout.log), [regresión](unitarias/scheduler-respaldo-regresion.stdout.log), [grupo de configuración](unitarias/configuracion-scheduler-android-ci.stdout.log), [canal local](integracion/scheduler-canal-sintetico.json), [protección](integracion/scheduler-proteccion-sintetica.json)).

Después de la autorización acotada se creó únicamente REPORTS_SCHEDULER_SECRET en el proyecto institucional, con una sola escritura. La lectura posterior comprobó en memoria la coincidencia del digest del nuevo valor y la conservación de los demás digests; los seis nombres personalizados requeridos quedaron presentes. La recuperación del archivo DPAPI almacenado coincidió con el valor vigente y los dos archivos cifrados se copiaron íntegros fuera del repositorio. No se publicaron valores o digests, no se enviaron mensajes ni se activaron tareas. La presencia del secreto no acredita que el scheduler o los proveedores entreguen notificaciones ([operación autorizada](seguridad/scheduler-secreto-creado.json), [recuperación y custodia](seguridad/scheduler-recuperacion-custodia.json)).

Se verificó la instalación del APK firmado mediante su hash y la presencia de MainActivity en primer plano a partir del registro ADB real. El ANR de System UI del emulador bloqueó la verificación visual y el intent de recuperación; no se presenta como un flujo funcional aprobado ni se atribuye ese ANR a RIOVOLEY ([resultado Android parcial](android/release-observaciones-parciales.json)).

No se ejecutaron nuevas suites Playwright, Jest del producto o compilaciones antes del corte de esta fase. Las cuatro regresiones del parser Android aprobaron con fixtures y no sustituyen una ejecución visual de la aplicación. Las alertas de Supabase, la RPC de ingreso diario del candidato y las comprobaciones controladas de proveedores permanecen fuera de los resultados aquí acreditados. Los ensayos y la configuración no sustituyen mediciones de usabilidad, motivación o escalas USE/UES-SF ([alcance y limitaciones](INFORME_VERIFICACION_TECNICA.md), [trazabilidad](MATRIZ_VERIFICACIONES_TESIS.md)).
