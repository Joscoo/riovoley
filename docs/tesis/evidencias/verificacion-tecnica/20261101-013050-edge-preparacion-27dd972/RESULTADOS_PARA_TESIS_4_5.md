# Texto académico propuesto para revisión: apartado 4.5

La verificación complementaria de las funciones Edge registró 35 contratos automatizados aprobados con dependencias simuladas, 12 pruebas HTTP de usuarios y notificaciones contra servicios locales reales y nueve pruebas HTTP de reportes, con denominadores independientes. Estas últimas comprobaron la generación de un PDF de padrón, la persistencia de su snapshot, la correspondencia entre tamaño y checksum del archivo, el uso de caché y el borrado del reporte sintético y su objeto Storage. Se verificaron también denegaciones para personal suspendido y el bloqueo de recordatorios sin secreto del scheduler. Los nueve entrypoints del candidato superaron la comprobación de tipos Deno después de corregir 23 errores detectados; los nueve bundles locales de retorno compilaron sin comprobación de tipos, por lo que este resultado se distingue de una validación funcional. Los registros y los intentos fallidos se conservan en [los resultados calculados](RESULTADOS_AUTOMATIZADOS.json) y [el informe](INFORME_VERIFICACION_TECNICA.md).

La preparación incluyó un complemento de permisos de reportes ensayado mediante avance y retorno SQL locales, y un ensayo de respaldo/restauración con datos sintéticos. El primer restore directo falló por la dependencia de una columna generada respecto de una función no inmutable; la adaptación documentada en otro destino local permitió recuperar la huella de catálogo y verificar seis tablas, sin modificar la base origen. Este ensayo no constituye un respaldo institucional ni una restauración de Supabase gestionado. La auditoría Deno del grafo npm candidato terminó con cero avisos, tras detectar inicialmente uno moderado, pero no cubrió todos los módulos HTTPS ni los proveedores reales. El contrato GoogleAuth utilizó SDK y firma reales con transporte OAuth simulado. No se repitieron en esta fase Playwright, compilación web ni Android, y no hubo despliegue o cambios institucionales. Permanecen pendientes el respaldo institucional comprobado, su restauración aislada y los requisitos operativos de publicación ([respaldo local](seguridad/backup-local-restaurado.json), [estado pendiente](seguridad/estado-respaldo.json)). Estas evidencias no se interpretan como mediciones de usabilidad o motivación.
