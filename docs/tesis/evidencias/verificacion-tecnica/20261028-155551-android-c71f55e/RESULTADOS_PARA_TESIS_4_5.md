# Propuesta académica complementaria: compilación Android

Como complemento de la verificación técnica, el 28 de octubre de 2026 se ejecutó una compilación nativa Android de RIOVOLEY mediante Capacitor y Gradle. Para superar las limitaciones del entorno inicialmente identificadas se prepararon JDK21 y Android SDK36 en una carpeta local aislada, conservando las fuentes y la configuración original del equipo. La sincronización de Capacitor reconoció siete plugins Android y finalizó correctamente. Posteriormente, el comando assembleDebug, junto con la tarea unitaria disponible, concluyó con código de salida cero; la última compilación posterior a la sincronización final duró **59,344 segundos** y generó un APK debug de **36793683 bytes**, con identificador com.riovoley.app, SDK mínimo24 y objetivo36. La firma del paquete se verificó mediante apksigner y su integridad se registró mediante SHA-256 ([compilación](android/gradle-assemble-1793214638542.meta.json), [sincronización](android/capacitor-sync-1793214589565.meta.json), [artefacto](android/artefacto-final.json)). Esta evidencia corresponde al empaquetado nativo y se distingue de la compilación web de React.

El análisis Android Lint final registró **cero errores y 29 advertencias**, relacionadas principalmente con iconos, recursos y versiones de dependencias; no se alteraron sus umbrales para obtener aprobación. La única prueba JUnit original ejecutada aprobó, pero corresponde a la plantilla aritmética 2+2=4 y no acredita funcionalidades del sistema ([Lint](android/lint/final/resumen.json), [JUnit](android/unitarias-final/resumen.json)). Durante la preparación se corrigieron incidencias del arnés relativas a la ruta del SDK y al aislamiento de variables. Un APK intermedio fue reservado al detectarse una clave pública institucional; el artefacto final se reconstruyó y superó la revisión de privacidad de sus miembros ZIP antes de la entrega, sin publicar credenciales ([retención de intermedios](android/retencion-intermedios.json), [privacidad previa](android/privacidad-previa-verificada.json)).

La comprobación se limitó a un perfil de empaquetado con configuración de prueba y actualizaciones OTA desactivadas en la copia; no utilizó claves institucionales de publicación ni configuración Firebase. ADB no detectó dispositivos conectados, por lo que las pruebas instrumentadas y el funcionamiento de la aplicación en Android permanecen **no ejecutados**. Tampoco se verificaron notificaciones FCM, permisos en ejecución, Auth nativo o distribución release ([dispositivos](android/dispositivos-final.json), [alcance](INFORME_VERIFICACION_TECNICA.md)). Los resultados permiten acreditar la generación verificable de un APK debug, sin atribuir validación completa de funcionalidades, seguridad, usabilidad, motivación o capacidad de interacción, ni resultados USE o UES-SF. Esta propuesta no modifica directamente el documento de tesis.
