# Propuesta para revisión académica: complemento del apartado 4.5

La preparación operativa del respaldo incorporó diez pruebas de contrato aprobadas para restringir el origen de conexión, exigir TLS verificado y filtrar variables heredadas. De forma separada, se ejecutó un flujo de integración con PostgreSQL 17.11 y GnuPG 2.4.9 sobre datos sintéticos. Este comprobó ocho controles relacionados con la lectura del catálogo, el rechazo de deriva o versión incorrecta, la exportación cifrada, la recuperación mediante la clave exportada en un llavero independiente, el rechazo de una frase incorrecta, la detección de un fallo de exportación y la identificación de corrupción del archivo. La copia cifrada del ensayo de entrega ocupó 53308 bytes y su tabla de contenido presentó 877 entradas; estos valores corresponden al laboratorio y no al volumen institucional ([contratos](unitarias/backup-final.stdout.log), [flujo sintético](integracion/backup-cifrado-entrega.json)).

Asimismo, se verificó el transporte TLS 1.3 hacia el servidor institucional sin intentar autenticación PostgreSQL. La inspección del archivo y el descifrado completo no constituyen una restauración de datos. La exportación institucional permanece bloqueada por la entrada local pendiente de la contraseña actual y de una frase de recuperación; por ello, tampoco se ha ejecutado su restauración aislada. En esta fase no se repitieron pruebas del producto con Jest, Playwright ni compilaciones web o Android, y no se aplicaron cambios al servicio institucional. Los intentos fallidos y las correcciones del entorno Windows se conservan en [el informe técnico](INFORME_VERIFICACION_TECNICA.md), junto con [los estados pendientes](RESULTADOS_AUTOMATIZADOS.json). Estas comprobaciones operativas no proporcionan mediciones de usabilidad o motivación.
